### C1 — `CliGitTrackingChecker` falha-fechada (Commit `74975cb0a`)
- **Problema corrigido:** Conforme apontado pelo Claude no parecer `docs/agents/reviews/2026-10-25_f047-t0-t2.md`, `CliGitTrackingChecker` falhava aberto (devolvia `false` em caso de erro, timeout ou ausência de git, oferecendo pastas com arquivos rastreados para exclusão).
- **Implementação em `CliGitTrackingChecker.cs` e `IGitTrackingChecker.cs`:**
  - `GitTrackingResult` enum adicionado: `Clean`, `HasTrackedFiles`, `CannotVerify`.
  - Distinção explícita entre **"não é repositório"** (`git rev-parse --is-inside-work-tree` com saída clara `false` ou stderr contendo `"not a git repository"`) e **"não consegui verificar"** (git ausente, erro de permissão/ownership, erro de execução ou timeout).
  - Em qualquer caso de erro, timeout ou ausência de git (`CannotVerify`), a verificação falha fechada: `HasTrackedFiles` retorna `true`, impedindo que a pasta de build seja oferecida pelo scanner (`continue;`).
  - Chamadas de processo convertidas para `ArgumentList` com `-C <pasta>` (`psi.ArgumentList.Add("-C"); psi.ArgumentList.Add(directoryPath); ...`), eliminando montagem manual de aspas em caminhos.
  - Leitura de saída assíncrona com limite rígido de caracteres (`maxChars: 1024` / `2048`) e tempo de espera controlado (`_timeoutMs = 3000`), matando a árvore do processo (`process.Kill(entireProcessTree: true)`) se o tempo limite for excedido, impedindo deadlocks de buffer de pipe.
  - Suporte a injeção de ambiente/binário para testes e isolamento de PATH (`ResolveBinary()` inspeciona `PATH` configurado em `_environment`).
- **Teste de controle negativo adicionado em `BuildFolderTests.cs`:**

## 5. Descobertas / Pendências
- **DISCOVERY (Comportamento Git no Windows):** Na máquina de desenvolvimento existe um repositório git em `C:\.git` com propriedade do TrustedInstaller. Quando `git rev-parse` é disparado em uma pasta sem `.git`, o git escala até a raiz `C:\` e aborta com erro de propriedade duvidosa (`detected dubious ownership in repository at 'C:/'`). A implementação de falha-fechada de C1 tratou este caso com máxima segurança: como a saída não é explicitamente `"not a git repository"`, o checker classifica como `CannotVerify` e não oferece os arquivos para exclusão por precaução.
