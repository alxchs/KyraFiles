### 1.1. FTPS Explícito / Implícito
- **Reconhecimento de esquema:**
  - O método `FtpHelpers.IsFtpPath` (`src/KyraFiles.App/Utils/Storage/Helpers/FtpHelpers.cs:25-27`) reconhece os esquemas `ftp://`, `ftps://` e `ftpes://`. CONFIRMED.
  - O método `FtpHelpers.GetFtpPort`:
    - Em `src/KyraFiles.App.Storage/Ftp/FtpHelpers.cs:33`: `return uri.Scheme.Equals("ftps", StringComparison.OrdinalIgnoreCase) ? (ushort)990 : (ushort)21;`. CONFIRMED.
    - Em `src/KyraFiles.App/Utils/Storage/Helpers/FtpHelpers.cs:54`: `if (index == -1) return path.StartsWith("ftps://", StringComparison.OrdinalIgnoreCase) ? (ushort)990 : (ushort)21;`. CONFIRMED.
- **Configuração de TLS / Criptografia:**
  - Em todas as instanciações de `AsyncFtpClient` (`src/KyraFiles.App.Storage/Ftp/FtpHelpers.cs:51`, `src/KyraFiles.App/Utils/Storage/StorageItems/FtpStorageFolder.cs:380`, `FtpStorageFile.cs:270`), o construtor é chamado passando apenas `(host, credentials, port)`:
    ```csharp
    return new(host, credentials, port);
    ```
    CONFIRMED.
  - Não é instanciado nem passado nenhum `FtpConfig` com `EncryptionMode`. CONFIRMED (`git grep -i "EncryptionMode" src/` retorna 0 ocorrências).
  - No FluentFTP, o valor padrão de `FtpConfig.EncryptionMode` é `FtpEncryptionMode.None`. Passar a porta 990 altera apenas o número da porta de conexão TCP, mas o cliente não inicia handshake TLS implícito nem envia comando `AUTH TLS` para TLS explícito sem a flag correspondente ou sem o uso de `AutoConnect()`.
  - **Conclusão:** O suporte a FTPS (explícito ou implícito) **não está funcionalmente ativo** no código atual; funciona apenas FTP convencional em texto puro. CONFIRMED.

### 1.2. Validação de Certificado
- Em nenhuma parte da solução existe referência a `ValidateAnyCertificate`, `OnValidateCert`, `ValidateCertificate`, `ServerCertificateCustomValidationCallback` ou inspeção de certificados X.509 para FTP. CONFIRMED via `git grep -i -E "ValidateCertificate|OnValidateCert|ValidateAnyCertificate" src/`.
- No FluentFTP, a propriedade padrão `FtpConfig.ValidateAnyCertificate` é `false` (delegada ao `SslStream` do .NET).
- Como o `EncryptionMode` atual permanece em `None`, nenhum handshake SSL/TLS é disparado na camada de transporte FTP, logo **nenhum certificado é recebido ou validado**. CONFIRMED.

### 1.3. Armazenamento e Tratamento de Credenciais
- **Local de armazenamento:**
  - As credenciais de FTP ficam unicamente em memória no dicionário estático `FtpManager.Credentials` (`Dictionary<string, NetworkCredential>`), localizado em `src/KyraFiles.App.Storage/Ftp/FtpManager.cs:10`. CONFIRMED.
  - Ao digitar credenciais na interface, `UIFilesystemHelpers.RequestPassword` atribui:
    ```csharp

    ```
    (`src/KyraFiles.App/Helpers/UI/UIFilesystemHelpers.cs:311`). CONFIRMED.
- **Ausência de persistência e proteção:**
  - As credenciais de FTP **NÃO são salvas em disco**. CONFIRMED.
  - As credenciais de FTP **NÃO usam DPAPI** (`ProtectedData`) e **NÃO usam o Windows Credential Locker** (`Windows.Security.Credentials.PasswordVault`). CONFIRMED.
  - O projeto possui `src/KyraFiles.App/Helpers/CredentialsHelpers.cs` que encapsula o `PasswordVault`, mas uma busca global no código comprova que essa classe é utilizada **única e exclusivamente para tokens de autenticação Git** (`GIT_RESOURCE_NAME` em `LibGit2Service.cs` e `GitHelpers.cs`). CONFIRMED via `git grep -n "CredentialsHelpers" src/`.
  - Na classe `StorageCredential` (`src/KyraFiles.App/Utils/Storage/StorageBaseItems/StorageCredential.cs:27-31`), a senha é convertida em string gerenciada plana quando acessada (`MarshalToString`). Em `NetworkCredential`, o valor reside descriptografado na memória gerenciada do processo.
  - Ao encerrar o aplicativo, todas as credenciais de FTP são descartadas; ao reabrir, o usuário é solicitado a digitar usuário/senha novamente. CONFIRMED.

### 1.4. Retomada de Transferência (Resume)

  - `CreateFileAsync` em `FtpStorageFolder.cs:227` invoca `ftpClient.UploadStream(stream, remotePath, ftpRemoteExists)`.
  - O parâmetro `ftpRemoteExists` só recebe `FtpRemoteExists.Overwrite` ou `FtpRemoteExists.Skip` (`src/KyraFiles.App/Utils/Storage/StorageItems/FtpStorageFolder.cs:216`). CONFIRMED.
- Nos downloads:

- O FluentFTP possui suporte a retomada (`FtpRemoteExists.Resume` e parâmetro `restartPosition`), mas o KyraFiles **não utiliza nenhum parâmetro de retomada**. CONFIRMED.
- Não há verificação de arquivo parcial existente, não há envio de comando `REST` e não há mecanismo de retomada após interrupção de rede. CONFIRMED.

2. `Microsoft.Extensions.Logging.Abstractions` (>= 8.0.3) — [https://www.nuget.org/packages/Microsoft.Extensions.Logging.Abstractions/](https://www.nuget.org/packages/Microsoft.Extensions.Logging.Abstractions/)

- **Impacto de Dependências no Projeto:**
  - `Microsoft.Extensions.Logging`: O projeto KyraFiles já referencia `Microsoft.Extensions.Logging` versão `10.0.12` em `Directory.Packages.props:42` e em `KyraFiles.App.csproj` e `KyraFiles.Shared.csproj`. Essa dependência já está resolvida e alinhada. CONFIRMED.
  - `BouncyCastle.Cryptography`: Não existe atualmente no projeto. É uma biblioteca puramente gerenciada para primitivas criptográficas (curvas elípticas Ed25519, NIST P-curves, ChaCha20-Poly1305, etc.). CONFIRMED via `git grep -i "BouncyCastle" Directory.Packages.props`.

### 2.5. Análise de Pegada / Tamanho do Pacote (NFR-004)
- **Requisito NFR-004 e Diretrizes do Alexandre:** Crescimento de pacote acima de 5 MB ou 10% exige justificativa técnica por escrito.
- **Tamanhos verificados:**
  - `SSH.NET.dll`: ~700 KB.
  - `BouncyCastle.Cryptography.dll`: ~6,0 MB a 7,2 MB descompactada (~4,0 MB a 5,0 MB no `.nupkg`).
- **Avaliação do Impacto:**
  O binário compilado de `BouncyCastle.Cryptography` ultrapassa ligeiramente a marca de 5 MB individuais.
  **Justificativa técnica necessária:** O .NET BCL (`System.Security.Cryptography`) não disponibiliza todas as primitivas de envelope necessárias para os algoritmos de chave e cifra modernos exigidos pelo protocolo SSH-2 (como Ed25519 KEX, chaves OpenSSH novas e certificados de host). O SSH.NET utiliza BouncyCastle como motor criptográfico padrão para garantir compatibilidade multiplataforma com servidores OpenSSH modernos.
  Portanto, essa dependência é justificada tecnicamente para atendimento a `REM-003` e `REM-012`, mas requer registro explícito no ADR-007. CONFIRMED.

### 2.6. Histórico de Vulnerabilidades Conhecidas (CVE)
- **CVE-2022-29245** (CVSS 5.9 — Médio):
  - *Problema:* Em versões 2020.0.0 e 2020.0.1 do SSH.NET, a chave privada efêmera do cliente para a troca de chaves X25519 era gerada usando `System.Random` em vez de um gerador criptograficamente seguro (`RandomNumberGenerator`).
  - *Mitigação:* Corrigido na versão 2020.0.2. A versão proposta (`2026.0.0`) não possui essa vulnerabilidade.
  - *Fonte:* NIST NVD ([https://nvd.nist.gov/vuln/detail/CVE-2022-29245](https://nvd.nist.gov/vuln/detail/CVE-2022-29245)). CONFIRMED.
- **CVE-2023-48795** (Terrapin Attack, CVSS 5.9 — Médio):
  - *Problema:* Vulnerabilidade arquitetural do protocolo SSH-2 que permite ataque Man-in-the-Middle com truncamento de pacotes na negociação de extensões.
  - *Mitigação:* O SSH.NET implementou suporte ao modo estrito de troca de chaves (`kex-strict-c-v00@openssh.com`) na versão 2024.0.0 e sucessoras.
  - *Fonte:* GitHub Advisory / Advisory Terrapin ([https://terrapin-attack.com/](https://terrapin-attack.com/)). CONFIRMED.
- **CVE-2026-48798** (CVSS 7.5 — Alto):
  - *Problema:* Path Traversal no cliente SCP (`ScpClient.Download`), onde o cliente aceitava nomes de arquivos remotos contendo sequências `../` ou caminhos absolutos, permitindo que um servidor malicioso sobrescrevesse arquivos fora do destino.
  - *Mitigação:* Corrigido na versão 2026.0.0. Além disso, o KyraFiles utilizará exclusivamente o protocolo SFTP (`SftpClient`), e não SCP (`ScpClient`).
  - *Fonte:* NIST NVD ([https://nvd.nist.gov/vuln/detail/CVE-2026-48798](https://nvd.nist.gov/vuln/detail/CVE-2026-48798)). CONFIRMED.

### 2.7. Alternativas Avaliadas
1. **FluentFTP:**
   - *Suporte a SFTP:* NENHUM. O FAQ oficial do FluentFTP esclarece categoricamente: *"Does FluentFTP support SFTP? No, SFTP is FTP over SSH which is a completely different protocol. Use SSH.NET instead."* ([https://github.com/robinrodricks/FluentFTP](https://github.com/robinrodricks/FluentFTP)). CONFIRMED.
2. **Rebex SFTP / Chilkat SFTP:**
   - *Licença:* Comercial proprietária / código fechado com royalties pagos. Incompatível com o projeto open source sob licença MIT. CONFIRMED.
3. **Tamir.SharpSSH:**
   - *Estado:* Projeto abandonado (última atividade há mais de 15 anos), sem suporte a .NET Core / .NET 10, sem suporte a cifras modernas (Ed25519, SHA-2). CONFIRMED.
4. **libssh2 (wrapper P/Invoke em C):**
   - *Restrições:* Exigiria empacotar binários nativos (`libssh2.dll`, `openssl.dll`/`zlib.dll`) para x64 e ARM64. Fere diretamente as diretrizes do projeto (`AGENTS.md`: *"Reject new uses of DllImport... Avoid ad hoc P/Invoke declarations"*). Alto risco de vazamento de memória e travamentos não gerenciados. CONFIRMED.

## 3. Registro e Integração de Locais de Rede/FTP no App

Sem desenhar a implementação da M3-T1, o mapeamento do código atual identifica exatamente onde locais remotos e URLs se conectam:

### 3.1. Barra de Endereços e Omnibar (`NavigationToolbarViewModel`)
- **Detecção de URL:**
  - Em `NavigationToolbarViewModel.cs:554` e `906`:
    ```csharp
    var isFtp = FtpHelpers.IsFtpPath(currentInput);
    var normalizedInput = NormalizePathInput(currentInput, isFtp);
    ```
    CONFIRMED.
  - `FtpHelpers.IsFtpPath` valida se a cadeia começa com `ftp://`, `ftps://` ou `ftpes://`.
  - Para SFTP: A extensão natural consiste em reconhecer `sftp://` (via helper de caminho) para impedir que a barra trate a URL como arquivo local do Windows (evitando adicionar drive letter ou inverter barras para `\`).
- **Navegação e Obtenção de Pasta:**
  - O Omnibar invoca `shellPage.NavigateToPath(normalizedInput)`, que por sua vez chama `StorageFileExtensions.DangerousGetFolderWithPathFromPathAsync` (`StorageFileExtensions.cs:270`). CONFIRMED.
  - `DangerousGetFolderWithPathFromPathAsync` delega para `BaseStorageFolder.GetFolderFromPathAsync(fullPath)`.
  - Em `BaseStorageFolder.cs:142-147`:
    ```csharp
    public static IAsyncOperation<BaseStorageFolder?> GetFolderFromPathAsync(string path)
    {
        return AsyncInfo.Run<BaseStorageFolder?>(async (cancellationToken)
            => await ZipStorageFolder.FromPathAsync(path) 
            ?? await FtpStorageFolder.FromPathAsync(path) 
            ?? await ShellStorageFolder.FromPathAsync(path) 
            ?? await SystemStorageFolder.FromPathAsync(path));
    }
    ```
    CONFIRMED.
  - De forma idêntica, `BaseStorageFile.GetFileFromPathAsync` (`BaseStorageFile.cs:168-173`) encadeia:
    ```csharp
    await ZipStorageFile.FromPathAsync(path) 
    ?? await FtpStorageFile.FromPathAsync(path) 
    ?? await ShellStorageFile.FromPathAsync(path) 
    ?? await NativeStorageFile.FromPathAsync(path) 
    ?? await SystemStorageFile.FromPathAsync(path);
    ```
    CONFIRMED.
  - **Ponto de acoplamento do provedor:** Um provedor `SftpStorageFolder.FromPathAsync(path)` e `SftpStorageFile.FromPathAsync(path)` entra nessa mesma cadeia de resolução polimórfica de storage.

### 3.2. Barra Lateral (`SidebarViewModel`)
- A barra lateral opera com seções fixas definidas pelo enum `SectionType` (`SidebarViewModel.cs:80-87`):
  `Home`, `Pinned`, `Library`, `Drives`, `CloudDrives`, `Network`, `WSL`, `FileTag`. CONFIRMED.
- **Seção `SectionType.Network`:**
  - O cabeçalho é montado em `SidebarViewModel.cs:590-595`.
  - A coleção de itens é provida por `NetworkService` (`StorageNetworkService.cs`):
    1. Computadores da rede local (`NetworkService.Computers`), descobertos via Shell do Windows (`Win32Helper.GetShellFolderAsync` sobre o GUID `::{f02c1a0d-be21-4350-88b0-7367fc96ef3c}`). CONFIRMED.
    2. Atalhos de rede (`NetworkService.GetShortcutsAsync`), lidos diretamente da pasta virtual `NetHood` do Windows (`PInvoke.FOLDERID_NetHood`, `%APPDATA%\Microsoft\Windows\Network Shortcuts`). Locais FTP criados pelo usuário no assistente do Windows Explorer aparecem automaticamente aqui como `DriveItem` com `Type = DriveType.Network`. CONFIRMED.
- **Seção `SectionType.Pinned`:**
  - Gerenciada por `PinnedFoldersManager` (`src/KyraFiles.App/Data/Models/PinnedFoldersManager.cs`).
  - Qualquer caminho válido aberto no KyraFiles (incluindo `ftp://...`) pode ser fixado pelo usuário via comando de menu de contexto "Fixar na barra lateral". CONFIRMED.
- **Constatação Arquitetural:** Não existe hoje nenhum botão ou diálogo interno "Adicionar conexão FTP" na barra lateral; o FTP existente entra apenas quando o usuário digita a URL no Omnibar, ou quando herdado do `NetHood` do Windows Explorer, ou quando fixado em `Pinned`. CONFIRMED.
