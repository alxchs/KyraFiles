## 1. Verificação das Afirmações do Plan

### 1.1 Caminho de Copiar/Mover/Colar e Ausência de Pausa no Motor Atual
- **Status:** **CONFIRMED**
- **Comando:**
  Inspeção de `src/Files.App/Utils/Storage/Operations/FileOperationsHelpers.cs:534-645` e `ShellFilesystemOperations.cs:81-95`.
- **Evidência no código:**
  O Files utiliza `ShellFileOperations2` encapsulando a API nativa `IFileOperation` do Windows Shell.
  A rotina `op.PerformOperations()` executa de forma bloqueante/síncrona na thread STA do `STATask`.
  A API nativa `IFileOperation` não provê método nem callback para pausar ou retomar uma cópia no meio do fluxo; apenas suporta cancelamento via flag de abortar. Assim, o motor atual é estritamente incapaz de pausar transferências.

### 1.2 O que `IsSpeedAndProgressAvailable` já Mostra no `StatusCenter`
- **Status:** **CONFIRMED**
- **Comando:**
  Inspeção de `src/Files.App/UserControls/StatusCenter/StatusCenter.xaml:165-245` e `src/Files.App/Utils/StatusCenter/StatusCenterItem.cs:106-225`.
- **Evidência no código:**
  `IsSpeedAndProgressAvailable` é ativado para operações em andamento (`canProvideProgress && Operation != FileOperationType.Git`). Quando o usuário expande o chevron (`IsExpanded = true`), o `StatusCenter` já renderiza o `SpeedGraph` com `SpeedGraphValues`, texto de velocidade em MB/s (`OperationSpeedStringTextBlock`) e porcentagem/progresso. Contudo, não há controle de fila nem botões de pausar/retomar.
