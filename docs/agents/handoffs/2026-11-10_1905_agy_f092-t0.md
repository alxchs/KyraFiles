### 2. Principais Conclusões e Evidências Técnicas (CONFIRMED)

1. **Causa Raiz de `hd-roteador` e `alxchs@gmail.com (lenovo)` não aparecerem:**
   - No Windows Explorer nativo, esses itens estão abaixo de "This PC" como *Delegate Folders* registradas em `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer\MyComputer\NameSpace\DelegateFolders` (`{289AF617-1CC3-42A6-926C-E6A863F0E3BA}` = DLNA Media Servers, `{b155bdf8-02f0-451e-9a26-ae317cfd7779}` = nethood delegate folder).
   - O namespace do Shell `NameSpace(17)` (`ssfDRIVES` / `shell:MyComputerFolder`) retorna 6 itens: os 3 discos montados (`C:\`, `D:\`, `R:\`) e os 3 servidores de mídia/dispositivos (`hd-roteador`, `alxchs@gmail.com (lenovo)` e `heloizedittrich@gmail.com (heloize-pc)`).
   - O KyraFiles hoje em `StorageDevicesService.cs` linha 21 chama exclusivamente a API .NET `DriveInfo.GetDrives()`, que filtra e obtém apenas volumes com letras de unidade fixas montadas, ignorando completamente qualquer delegate folder do Shell.

2. **Capacidade de Navegar no Conteúdo de Itens Virtuais:**
   - `SHCreateItemFromParsingName` nativo retorna `hr = 0` (`SUCCESS`) para o parsing name `::{20D04FE0-3AEA-1069-A2D8-08002B30309D}\uuid:4d696e69-444c-164e-9d41-000000008fbe`.
   - `GetFolder` enumera 4 subpastas (`Browse Folders`, `Music`, `Pictures`, `Video`), e dentro de `Browse Folders` enumera com sucesso os subitens reais do disco (`$RECYCLE.BIN`, `15Victoria`, `Assistir`).
   - `ShellStorageFolder` do KyraFiles já suporta parsing names iniciados por `::{` (`IsShellPath`).
   - Conforme alinhado com o Alexandre: se algum item virtual falhar na enumeração interna do KyraFiles, será exibido aviso claro e oferecida a opção "Abrir no Explorador do Windows".

3. **Métricas de Baseline:**
   - `DriveInfo.GetDrives()`: 1.58 ms (3 itens).
   - `Shell NameSpace(17)`: 519.63 ms (6 itens).
   - `UI Startup`: Declarado `NOT TESTED` (horário pré-23:59, preservação mandante de foco da tela do usuário).
