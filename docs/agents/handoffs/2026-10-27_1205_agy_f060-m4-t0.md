## 1. O que deu certo

1. **Pesquisa em fontes públicas oficiais (nuget.org e GitHub):**
   - **MoonSharp (Lua):** versão `2.0.0` (14/10/2016), licença BSD-3-Clause, TFM .NET Standard 2.0 / .NET Framework 3.5+, 0 dependências, manutenção baixa/recente retomada com `3.0.0-beta.1` em julho/2026, 0 CVEs centrais.
   - **Jint (JavaScript):** versão `4.17.0` (07/10/2026), licença BSD-2-Clause, multi-targeting com suporte nativo a `net10.0`, 0 dependências, manutenção muito ativa, 0 CVEs no motor central.

2. **Protótipo console fora de `src/` (`tools/perf/ScriptEngineSpike`):**
   - Construído sem tocar em nenhum arquivo de `src/` ou `tests/`.
   - Mediu e comparou os 5 critérios estabelecidos:
     - (a) Carga e execução de script trivial (`10 + 32`): MoonSharp 188,00 ms; Jint 705,25 ms.
     - (b) Timeout em laço infinito: Jint interrompido nativamente em 2.017,50 ms (`TimeoutException`); MoonSharp interrompido em 2.000,10 ms via corrotina com `AutoYieldCounter`.
     - (b.2) Cancelamento via `CancellationToken`: Jint interrompido em 507,49 ms (`ExecutionCanceledException`). MoonSharp não suporta `CancellationToken` nativo no despachante.
     - (c) Limite de memória: Jint barrou script alocador em 114,74 ms (`MemoryLimitExceededException` para cota de 2 MB). MoonSharp **não** oferece medidor/limite de memória.
     - (c.2) Limite de instruções/statements: Jint barrou em 5,72 ms (`StatementsCountOverflowException` em 500 statements). MoonSharp barrou em 26,43 ms via contador de ciclos de corrotina.
     - (d) API Restrita: Ambos executaram chamadas legítimas em fachadas `fs` e `log` (2 logs gerados).
     - (d) Fuga de sandbox:
       - MoonSharp: `os.execute` e `io.open` bloqueados (`nil`) via `CoreModules.Preset_HardSandbox`. Tipos CLR não registrados são invisíveis.
       - Jint: `System.IO.File`, `Process.Start`, `require`, `import` e reflexão via construtor de função (`this.constructor.constructor`) foram rigorosamente bloqueados sem vazamento para o host.
     - (e) Pico de memória do processo: MoonSharp 52 MB; Jint 53 MB.

## 2. O que deu errado / Dificuldades e Achados

1. **Central Package Management (CPM) no repositório:** Ao criar o spike, o build inicial falhou com `error NU1008` porque a raiz impõe CPM via `Directory.Packages.props`. Para respeitar a regra de não alterar arquivos globais nem `src/`, foi configurado `<ManagePackageVersionsCentrally>false</ManagePackageVersionsCentrally>` exclusivamente dentro do `.csproj` do spike em `tools/perf/ScriptEngineSpike/`.
2. **Descoberta do Sandbox do MoonSharp:** O método padrão `script.DoString(...)` roda de forma síncrona e ininterruptível em caso de laço infinito. Para possibilitar timeout ou limite de instruções no MoonSharp, é mandatório carregar o script como função, instanciar uma `Coroutine`, definir `AutoYieldCounter` e tratar o estado `CoroutineState.ForceSuspended` em um loop de C# com verificação manual de cronômetro. Além disso, MoonSharp não tem como limitar memória alocada.
3. **Descoberta de Worktree Git:** O helper de busca da raiz do repositório inicialmente procurava `.git` como diretório; em um worktree git, `.git` é um arquivo de texto apontando para `gitdir: ...`. O helper foi ajustado para `File.Exists || Directory.Exists`.
