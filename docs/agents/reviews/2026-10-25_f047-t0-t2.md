## Veredito: ACEITA COM 3 CORREÇÕES (uma delas de segurança)

### C1 (SEGURANÇA, bloqueia a T3): o verificador de git falha aberto
`CliGitTrackingChecker.HasTrackedFiles` devolve `false` ("nada rastreado") quando o `git` não existe, o processo não inicia, estoura qualquer exceção, o `ExitCode` é diferente de 0 ou **o `WaitForExit(3000)` expira**. Dentro de um repositório isso **oferece para exclusão uma pasta com arquivos rastreados**, que é exatamente o risco que o FR-002 existe para impedir. Correção: distinguir **"não é repositório"** (`git rev-parse --is-inside-work-tree` com saída clara `false`/exit 128 pelo motivo "not a git repository") de **"não consegui verificar"**; neste segundo caso o item **não é oferecido** (falha fechada) e o motivo vai para o diálogo. Teste obrigatório (controle negativo): com o `git` inacessível (`PATH` sem git, via `ProcessStartInfo.Environment`), uma pasta **dentro de um repositório** com arquivo rastreado **não** é oferecida. Também: ler a saída com limite e tempo (hoje `ReadToEnd` antes do `WaitForExit` pode bloquear), e usar `-C <pasta>` com `ArgumentList` em vez de montar aspas à mão (caminho com `"`).

### C2: evidência de medição malformada
`nfr001_scan_200_projects.csv` tem 4 colunas no cabeçalho e 5 nas linhas: a vírgula decimal da cultura pt-BR (`{ms:F2}`) virou separador (`344,14` lido como duas colunas). É o erro (d) do padrão 7 do `INSTRUCTIONS_OPERARY.md`. Correção: `CultureInfo.InvariantCulture` e ponto decimal. Além disso: o teste **regrava** o CSV de evidência a cada execução (o `git status` do worktree ficou sujo depois da minha execução): a evidência deve ir para uma pasta temporária e só ser copiada de propósito.

### C3: medição fraca
200 projetos sintéticos pequenos varridos em 0,28 a 0,55 s provam o NFR-001 (meta 30 s) para árvore **rasa**, sem `node_modules` real nem profundidade. O handoff chama de "benchmark"; é **OBSERVED, n = 3, árvore sintética rasa**. Incluir uma árvore com um `node_modules` de ~50 mil arquivos (gerado pelo teste, apagado ao fim) para provar a **poda** (o scanner não pode entrar nele). Sem isso o NFR-001 fica `INFERRED`.
